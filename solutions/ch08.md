## Programming exercises

**8.9** Implement $K$-fold cross-validation from scratch and use it to choose the optimal degree of a polynomial for the data of Exercise 1.11. Compare the result with a simple train–test split.

```python
import numpy as np
 
def kfold_error(x, y, degree, K=5, seed=0):
    idx = np.random.default_rng(seed).permutation(len(x))
    folds = np.array_split(idx, K)
    errs = []
    for k in range(K):
        te = folds[k]; tr = np.hstack(folds[:k] + folds[k+1:])
        c = np.polyfit(x[tr], y[tr], degree)
        errs.append(np.mean((np.polyval(c, x[te]) - y[te]) ** 2))
    return np.mean(errs)
```

## Solutions

**Solution 8.1.** Squared loss: $\frac{d}{dc}\sum_{n}^{}\left( y_{n} - c \right)^{2} = - 2\sum_{n}^{}\left( y_{n} - c \right) = 0$ gives $c = \frac{1}{N}\sum_{n}^{}y_{n}$. Absolute loss: the subgradient $\sum_{n}^{}{sign}\left( c - y_{n} \right)$ is zero when the numbers of labels below and above $c$ are equal; that is, $c$ is the median.

**Solution 8.2.** The negative log-likelihood is $\frac{N}{2}\log\left( 2\pi\sigma^{2} \right) + \frac{1}{2\sigma^{2}}\sum_{n}^{}r_{n}^{2}$, where $r_{n} = y_{n} - \mathbf{x}_{n}^{\top}\mathbf{\theta}$. Its derivative with respect to $\sigma^{2}$ is $\frac{N}{2\sigma^{2}} - \frac{1}{2\sigma^{4}}\sum_{n}^{}r_{n}^{2}$, and setting it to zero gives $\sigma_{ML}^{2} = \frac{1}{N}\sum_{n}^{}r_{n}^{2}$. For the data of Table 8.2 this value is about 656 (Example 8.5).

**Solution 8.3.** $- \log p\left( \mathbf{\theta} \right) = \frac{1}{b}\sum_{d}^{}\left| \theta_{d} \right| + \text{const}$. Hence MAP minimises $\frac{1}{2\sigma^{2}} \| \mathbf{y} - \mathbf{X}\mathbf{\theta} \|^{2} + \frac{1}{b} \| \mathbf{\theta} \|_{1}$, which after multiplication by $2\sigma^{2}$ is exactly the Lasso with $\lambda = 2\sigma^{2}/b$.

**Solution 8.4.** The edges of Figure 8.9(b) are $x_{1} \rightarrow x_{3}$, $x_{2} \rightarrow x_{3}$, $x_{5} \rightarrow x_{2}$ and $x_{2} \rightarrow x_{4}$, so the joint distribution factorises as in (8.30):

$$p\left( x_{1},\ldots,x_{5} \right) = p\left( x_{1} \right)p\left( x_{5} \right)p\left( x_{2} \mid x_{5} \right)p\left( x_{3} \mid x_{1},x_{2} \right)p\left( x_{4} \mid x_{2} \right).$$

The only path between $x_{1}$ and $x_{5}$ is $x_{1} \rightarrow x_{3} \leftarrow x_{2} \leftarrow x_{5}$. (a) Yes. At $x_{3}$ the arrows meet head-to-head, so $x_{3}$ is a collider; since neither $x_{3}$ nor any of its descendants (it has none) is observed, the path is blocked and $x_{1} \perp\!\!\!\perp x_{5}$. This can also be checked directly: summing the factorisation over $x_{2},x_{3},x_{4}$ leaves $p\left( x_{1},x_{5} \right) = p\left( x_{1} \right)p\left( x_{5} \right)$. (b) No (in general). Observing the collider $x_{3}$ unblocks the path at $x_{3}$, and at $x_{2}$ the arrows meet head-to-tail with $x_{2}$ unobserved, so the path is open and $x_{1}$ and $x_{5}$ become dependent given $x_{3}$ — the "explaining away" effect.

**Solution 8.5.** If a hyperparameter is selected with the test set, the selected model has been "fitted" to that same data, and its error on that set is an optimistic estimate. In nested cross-validation, the inner loop selects the hyperparameter using only the training data, and the outer loop evaluates the selected model on data that were not used in any decision.

**Solution 8.6.** (a) The data are highly imbalanced; accuracy is misleading, and precision, recall or the area under the precision–recall curve are more suitable. (b) The mean absolute error or the root-mean-squared error, in units of price. (c) Ranking metrics such as precision at k or nDCG, because the order of the results matters.

**Solution 8.7.** Examples: (1) standardising the whole data set before splitting; remedy: fit the scaler on the training data only. (2) A feature recorded after the target event, such as "discharge date" when predicting mortality; remedy: check when each feature is recorded. (3) Several images of the same patient in both sets; remedy: split by patient rather than by image.

**Solution 8.8.** In the functional view, the predictor gives a single number for age 60, for example 136 thousand. In the probabilistic view, we obtain a distribution such as $\mathcal{N}(136,\mspace{6mu} 656)$, which also reports the plausible range of the salary. Only the probabilistic view makes it possible to express uncertainty.

**Solution 8.9.** The degree selected by cross-validation is usually 3 to 5; a simple split fluctuates more because it depends on a single random split. The complete code is in the book's repository.

**Solution 8.10.** Sort the scores and, for each threshold, compute the true-positive and false-positive rates; the area under the curve is obtained with the trapezoidal rule and agrees with roc_auc_score up to rounding error.

**Solution 8.11.** For data with few samples and many features, standardising before splitting usually inflates the reported accuracy by a few percentage points above its true value; this gap grows as the number of samples decreases.
